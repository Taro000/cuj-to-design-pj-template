# AI の作業手順

- 人間からの依頼は、Slack のチャンネルでの `@Claude` メンションで届く（Claude Code in Slack）。セッションはクラウドで動き、最後の返答が依頼したメッセージのスレッドに表示される。
- Dependabot の PR だけは、`.github/workflows/claude-cloud.yml` が Routine を起動して届く（`mode: dependabot`）。
- ラベルは手番の目印で、付けても AI は起動しない。
- どの入口から始まっても、この手順で作業する。

## 依頼を受けたら

1. 依頼文とスレッドの内容から、対象の Issue / PR を特定する。
   - 調査・要件定義・設計・実装を伴う依頼で、対応する Issue が無ければ、先に Issue を作って `未着手` を付ける（本文は `pr-issue-body.md` に従う）。
   - 質問に答えるだけの依頼では Issue を作らない。
2. 対象に `AI's Turn` を付ける（`Human's Turn` はワークフローが外す）。
3. スレッドで人間が決めたこと（「判断してほしいこと」への回答など）があれば、対象にコメントで書き写す。Slack のメッセージは記録として残らない前提で扱う。

## 段階の進め方

- 状態ラベルは `未着手` → `要件定義` → `設計` → `実装` の順に進める。`Stg` / `Prd` はリリース後の状態なので、AI の作業では付けない。
- 依頼で指定された段階まで進める。指定が無ければ、今の段階の次を 1 つだけ進める。
- 各段階でやること
  - `要件定義`: Issue 本文の「何を・なぜ」と「受け入れ条件」を書く。決められない点は「判断してほしいこと」に挙げる。
  - `設計`: Issue 本文の「実装方針（How）」を書く。PR が `L` になりそうなら、サブタスクに分ける（`issue.md`）。
  - `実装`: `<種別>/<説明>` のブランチで実装し、`stage` 向けの PR を作る（`hotfix` は `main` 向け）。
- 段階を終えたら、状態ラベルをその段階に付け替える（例: `未着手` の Issue に要件定義を書いたら `要件定義` にする）。

## PR についての依頼

- レビュー指摘への対応では、未解決の指摘に対応し、その PR のブランチに push する。新しいブランチや PR は作らない。
- Dependabot の PR では、リリースノートで破壊的変更を確認し、テスト・ビルド・lint を実行する。失敗したら、その PR のブランチに互換対応のコミットを足す。マージしてよいか、懸念は何かを PR にコメントする。マージはしない。

## 終わったら

1. 対象に `Human's Turn` を付ける（`AI's Turn` はワークフローが外す）。PR を作ったときは、Issue と PR の両方に付ける。
2. 対象にコメントする（PR を作ったときは PR に）。クラウドセッションでは、最後にセッションの URL を書く（`echo "https://claude.ai/code/${CLAUDE_CODE_REMOTE_SESSION_ID/#cse_/session_}"` で得られる）。

   ```markdown
   ### やったこと

   - 

   ### 判断してほしいこと

   - （無ければ「なし」）

   セッション: https://claude.ai/code/session_...
   ```

3. 最後の返答は次の形で、10 行以内にまとめる。Slack から依頼された場合、この返答がそのままスレッドに表示される。詳しい内容は 2 のコメントに書いたので、返答には要約とリンクだけを書く。見出しと表は Slack で崩れるので使わない。

   ```text
   <結果を 1 行で>
   対象: #<番号> <タイトル>（<作業前の状態> → <作業後の状態>）
   成果: <コメントや PR の URL>
   判断してほしいこと: <1〜3 個。無ければ「なし」>
   ```

   - 質問に答えるだけの依頼では、この形にしなくてよい。

## クラウドセッションでの GitHub 操作

- 指示が無いと、クラウドセッションは `claude/` で始まるブランチに push する。実装を始める前に `<種別>/<説明>` のブランチを作って切り替える。
- `gh issue` / `gh pr` は GraphQL を使うため、プロキシに拒否される。組み込みの GitHub ツールか `gh api`（REST）を使う。

  ```sh
  # ラベルを付ける・外す（Issue と PR は同じ API）
  gh api repos/{{REPO}}/issues/<番号>/labels -f "labels[]=Human's Turn"
  gh api -X DELETE "repos/{{REPO}}/issues/<番号>/labels/要件定義"
  # Issue・PR を作る（本文はファイルから渡す）
  gh api repos/{{REPO}}/issues -f title="<説明>" -F body=@<本文のファイル> -f "labels[]=未着手"
  gh api repos/{{REPO}}/pulls -f base=stage -f head=<ブランチ> -f title="<種別>: <説明>" -F body=@<本文のファイル>
  ```
